# Задача: масштабная переработка Graphics Programmer Roadmap

Сайт: https://heaven-seeker.github.io/graphics-road/

Репозиторий: https://github.com/heaven-seeker/graphics-road

Я хочу, чтобы ты существенно переработал мой существующий сайт для обучения компьютерной графике. Это не косметическое обновление: нужно пересмотреть структуру знаний, граф зависимостей, учебный маршрут, систему источников и взаимодействие пользователя с сайтом.

**Главная цель — создать подробную, структурированную, технически грамотную и удобную карту знаний для развития до сильного Graphics/Rendering Programmer уровня игровой индустрии.**

Это мой персональный инструмент для многолетнего обучения, а не вводный курс для абсолютного новичка.

Работай с существующим репозиторием. Сначала изучи его архитектуру, данные, состояние интерфейса и текущую логику прохождения. Затем реализуй улучшения непосредственно в коде.

Я уже не новичок в графическом программировании.

Мой опыт:
- C++20, CMake, SDL3.

- Курс Pikuma по компьютерной графике.
- Собственные эксперименты с GPU, текстурами, compute shaders, буферами, depth testing, blending.
- Базовая линейная алгебра, матрицы преобразования, камера, проекции.
- Начальное изучение Vulkan.
- Практика с WGSL и основы GLSL.
- Понимание основных стадий graphics pipeline.

**Основной графический API теперь Vulkan.** WebGPU остаётся частью моего предыдущего опыта, но не должен быть обязательной ступенью основного маршрута.

Основной язык — C++20. Хочу использовать Vulkan для создания собственного 3D Viewer, который постепенно вырастет в полноценный учебный renderer.

В будущем интересуют:

- глубокое понимание математики, освещения и алгоритмов;

Ориентир профессиональной глубины — rendering/graphics programmer в игровой студии уровня Saber Interactive.

Не делай из моего маршрута исключительно подготовку к собеседованиям. Главное — реальные знания, самостоятельная практика и инженерные навыки.

## 2. Главная проблема текущего дерева

Сейчас дерево слишком крупнозернистое.

Например, один узел «Освещение» может включать десятки практически независимых тем: Phong, BRDF, PBR, радиометрию, Fresnel, различные виды источников света.

Это неправильно для моего способа обучения.

Я хочу видеть конкретные технические понятия, алгоритмы и технологии как отдельные узлы.

Пример желаемой декомпозиции:

Освещение
- Radiometry
  - Radiant flux
  - Radiance
  - Irradiance
  - Solid angle
- Local illumination
  - Lambert diffuse
  - Phong
  - Blinn-Phong
  - Attenuation
- BRDF
  - Rendering equation
  - Diffuse BRDF
  - Specular BRDF
  - Energy conservation
  - Reciprocity
- Microfacet models
  - Normal Distribution Function
  - GGX
  - Geometry / masking-shadowing
  - Smith model
  - Fresnel equations
  - Schlick approximation
  - Cook-Torrance
- PBR
  - Metallic-roughness workflow
  - Material parameterization
  - Image-Based Lighting
  - Diffuse irradiance
  - Specular prefiltering
  - Split-sum approximation

Это пример, а не исчерпывающая схема. Разработай более точную структуру сам.

Важно: PBR как подход к рендерингу и PBRT как книга/область изучения физически корректного рендеринга — не одно и то же. Не смешивай сущности, алгоритмы и учебные источники.

**Стремись к атомарным узлам, но избегай искусственного дробления.** Если тема достаточно большая для отдельного изучения и практического результата — она заслуживает отдельного узла. Не создавай бесполезные карточки только ради увеличения их количества.

## 3. Полностью расширь техническую карту знаний

Нужно систематически охватить следующие направления, каждое с подробным разбиением.

### A. Математика для графики
Векторы, матрицы, пространства координат, преобразования, projection matrices, quaternions, интерполяция, barycentric coordinates, derivatives, calculus, probability, Monte Carlo integration, numerical precision, geometric computations.

Базовые темы должны быть доступны как справочник или проверка знаний, а не обязательно повторяться с нуля.

### B. Vulkan и Low-Level Graphics API
Instance, validation layers, physical/logical devices, queues, swapchain, image views, command pools, command buffers, GPU memory, VMA, buffers, images, image layouts, barriers, synchronization2, semaphores, fences, descriptors, descriptor indexing, pipeline layouts, dynamic rendering, pipeline creation, shader modules, push constants, staging uploads, resource lifetime, multithreaded recording и многое другое.

Раздели Vulkan на небольшие логически связанные концепции. Для каждого важного механизма должна быть самостоятельная задача.

Изучение Vulkan не должно ограничиваться созданием треугольника.

### C. Graphics Pipeline
Vertex processing, clipping, primitive assembly, rasterization, fragment processing, depth/stencil tests, interpolation, perspective-correct interpolation, viewport transformations, early/late Z, face culling, instancing, draw calls, indirect drawing.

### D. Shaders
GLSL, SPIR-V, vertex shaders, fragment shaders, compute shaders, shader math, SDF, procedural patterns, noise, derivatives, fwidth, anti-aliasing, ray marching, normal mapping, displacement, shader debugging, optimization.

Добавь небольшие творческие упражнения, которые учат самостоятельно создавать изображения с помощью математических функций.

### E. Геометрия и структуры данных
Обязательно выделить отдельные узлы:
- AABB, OBB, bounding sphere;
- frustum culling;
- spatial hashing;
- uniform grid;
- octree;
- quadtree;
- k-d tree;
- BVH;
- SAH;
- BVH construction/traversal;
- scene graph;
- spatial partitioning;
- meshlets;
- LOD и другие структуры и алгоритмы.

Для каждого — назначение, теория, реальные применения, преимущества и ограничения, практическая реализация.

Не объединяй BVH, octree и k-d tree в один учебный узел.

### F. Materials, Lighting, PBR
Максимально подробно раскрыть свет, радиометрию, BRDF, модели освещения, материалы, микрофасеточные модели, reflection/refraction, Fresnel, environment lighting и остальные важные понятия.

### G. Shadows
Shadow mapping, PCF, bias, peter-panning, cascaded shadow maps, variance shadow maps, soft shadows, contact shadows, shadow filtering.

### H. Texturing and Color
UV, mipmaps, filtering, anisotropic filtering, texture compression, HDR, linear/sRGB, gamma, color spaces, exposure, tone mapping, normal maps, parallax mapping.

### I. Ray Tracing
Ray generation, intersections, acceleration structures, reflection/refraction, recursive ray tracing, path tracing, Monte Carlo sampling, importance sampling, MIS, denoising, Vulkan ray tracing extensions, RT pipelines.

### J. Global Illumination
Rendering equation, light transport, path tracing, light probes, irradiance volumes, voxel-based GI, screen-space techniques, ReSTIR, DDGI и другие подходы.

Разделяй фундамент, классические алгоритмы, современные технологии и исследования.

### K. Post-processing
Bloom, SSAO, GTAO, SSR, TAA, motion vectors, motion blur, depth of field, temporal accumulation, denoising, upscaling.

### L. GPU Architecture / Performance
GPU execution model, warps/wavefronts, SIMD/SIMT, memory hierarchy, caches, occupancy, divergence, coalescing, bandwidth, latency, synchronization, async compute, profiling, performance analysis.

### M. Renderer / Engine Architecture
Resource management, scene representation, asset pipelines, draw submission, batching, render graph, frame graph, synchronization architecture, GPU-driven rendering, streaming, multithreading, job systems, serialization, profiling, debugging.

### N. Animation and Advanced Rendering
Skeletal animation, skinning, morph targets, GPU animation, particles, volumetrics, atmosphere, fog, terrain, water rendering, transparency/OIT, mesh shaders, virtual texturing и другие значимые темы.

### O. Инженерные инструменты
RenderDoc, Radeon GPU Profiler, validation layers, debugging, unit/integration tests, CMake, CI, sanitizers, profiling, GPU capture analysis.

**Не ограничивайся моим списком.** Используй профессиональное понимание graphics programming, чтобы дополнить отсутствующие темы.

Цель — полноценная карта знаний от intermediate до advanced/expert, а не случайный список модных технологий.

## 4. Построй настоящий граф зависимостей

Нынешняя программа слишком похожа на последовательность крупных разделов. Я хочу осмысленный направленный граф зависимостей (DAG).

Например:

- Perspective projection → Frustum → Frustum culling.
- Bounding volumes → BVH → BVH traversal.
- Radiometry → BRDF → Microfacet theory → Cook-Torrance → PBR.
- Texture sampling → Mipmaps → Filtering → Anisotropic filtering.
- GPU synchronization → Multi-pass rendering → Render graph.
- Ray intersections + acceleration structures → Ray tracing → Path tracing.

Зависимости должны быть технически обоснованы.

Различай:
- обязательные prerequisites;
- рекомендуемые знания;
- независимые направления;
- дополнительные углубления.

Не заставляй проходить весь предыдущий раздел только потому, что следующий расположен ниже на странице.

Если я уже знаю матрицы и умею работать с буферами, я должен иметь возможность перейти к интересующей теме без бессмысленного повторения.

## 5. Полностью переработай интерфейс дерева

Дерево должно стать главным элементом сайта.

Я хочу, чтобы оно было большим по содержанию, но не перегружало экран.

Реализуй многоуровневую иерархию:

1. Направление (например, Lighting).
2. Раздел (например, BRDF).
3. Конкретная тема (например, GGX).
4. Практические шаги внутри карточки темы, когда это необходимо.

При этом реальные зависимости между темами должны существовать независимо от визуальной группировки.

Желаемые возможности:
- Масштабирование и перетаскивание.
- Сворачивание и разворачивание направлений.
- Режим обзора всей карты.
- Фокус на конкретном направлении.
- Подсветка обязательных предшествующих тем.
- Отображение доступных, изученных и активных узлов.
- Поиск по алгоритмам, источникам и технологиям.
- Фильтр по сложности, категории, прогрессу и типу деятельности.
- Возможность скрыть уже известные базовые темы.
- Кнопка «Продолжить обучение».
- Кнопка «Показать путь к этой теме».
- Кнопка «Что изучать дальше?».

Не обязательно рисовать сотни узлов одновременно. Предусмотри разные уровни детализации и удобную навигацию.

Никакого огромного нечитаемого полотна с пересекающимися стрелками.

Сохрани визуальную привлекательность сайта, но приоритет — функциональность и понятность.

## 6. Переработай «Программу»

Сейчас «Программа», «Дерево», «Сегодня» и дополнительные страницы частично конкурируют друг с другом. Мне непонятно, какой экран должен быть основным.

Самостоятельно проанализируй их назначение.

Я предлагаю новую архитектуру:

**Дерево** — полная интерактивная карта знаний.

**Мой путь** — автоматически вычисляемая последовательность ближайших тем на основе графа зависимостей, выбранных целей и моего прогресса.

**Сегодня** — одна текущая тема и конкретное небольшое действие, с которого можно сразу начать.

**Библиотека** — книги, статьи, лекции, документация, связанные с конкретными темами.

**Проекты** — практическая реализация изученных знаний.

Если существующая «Программа» избыточна, удали её или преврати в компактный учебный маршрут.

Не поддерживай две независимые базы данных с почти одинаковыми задачами.

Единым источником истины должны быть знания и их связи, на основе которых генерируются остальные представления.

## 7. Сделай каждую карточку темы действительно полезной

Нажатие на узел должно открывать полноценную карточку.

Пример: BVH

- Название и категория.
- Уровень сложности.
- Что это такое — короткое объяснение.
- Для чего применяется.
- Какие знания нужны заранее.
- Что конкретно нужно понять.
- Какие источники прочитать.
- Практическая задача.
- Дополнительная сложная задача.
- Вопросы на понимание.
- Критерий завершения.
- Какие темы открываются дальше.
- Поле заметок.
- Статус изучения.

Нужны конкретные критерии, а не просто «прочитать про BVH».

Например: реализовать построение BVH для набора треугольников, ray-AABB traversal, сравнить число проверок пересечений с brute-force.

Для теоретических тем критерий может быть другим: объяснить уравнение, самостоятельно вывести частный случай, проверить математическое свойство на числовом примере.

Не заставляй реализовывать отдельный проект ради каждого определения.

## 14. Как выполнять работу

Сначала проведи аудит текущего репозитория: структура данных, навигация, логика зависимостей, избыточные страницы, реальные проблемы UX, сохранение прогресса.

Затем спроектируй новую модель и начни её внедрение.

Приоритет:

1. Правильная предметная структура.
2. Граф зависимостей.
3. Полезные атомарные карточки.
4. Интеграция источников.
5. Понятный маршрут и навигация.
6. Удобное интерактивное дерево.
7. Визуальная полировка.

Выполняй работу итерациями. Первая реализация должна быть полностью работоспособной, а не просто содержать сотни незаполненных карточек.

Внедри достаточно полное и подробное покрытие основных тем. Если для качественного результата требуется несколько сотен узлов — это нормально. Но число узлов не является самоцелью.

Обнови документацию и автоматические тесты.

Запусти применимые проверки проекта:
- npm test
- npm run test:browser
- npm run docs

Если какое-то окружение или зависимость недоступны, сообщи точно, что не удалось проверить.

В конце предоставь:
- что именно изменено;
- новую структуру знаний;
- как теперь работает дерево;
- как используются источники;
- что произошло со старой программой;
- как сохранён прогресс;
- какие тесты выполнены;
- какие ограничения остались.
